# 隱私與敏感資訊檢查

> 檢查日期：2026-09-21
>
> 基準：2026-09-21 歷史重寫前的 main，並複核本次文件更新後的工作樹。

## 結論

在當時所有可達的 Git commit 中，未找到可辨識的正式密碼、private key、GitHub token、AWS access key、Google API key、OpenAI-style key 或硬編碼 secret。這是規則比對與人工複核，不等同完整 entropy scanner，也沒有讀取正式主機、GitHub Secrets、資料庫或執行期 log。

`main` 原本含有下列可識別的部署資訊，本次已從目前版本移除：

- 正式服務網域、憑證目錄與 nginx log 檔名。
- nginx 註解中的一個公開 IPv4；它可能暴露 origin 或管理者來源資訊。
- 多處看似由真實設定衍生的 Cognito user pool ID / app client ID 範例。這些 ID 本身不是密碼，但屬 operational metadata。
- workflow summary 中固定的對外健康檢查網址。

歷史 commit 仍保留上述舊值與 Git author email。本次沒有改寫 Git 歷史，因為歷史重寫會改變所有既有 commit ID，並影響已拉取 repo 的工作副本。若網域、IP 或作者信箱仍需保密，應先輪替／停用對應資源，再另行規劃 coordinated history rewrite。

## 檢查方法

使用 `git rev-list`、`git grep` 與目前工作樹的定向搜尋，範圍涵蓋所有可達 commit tree。比對類型包括：

- PEM private-key header。
- `gh[pousr]_...`、`github_pat_...`、`AKIA...`、`AIza...`、`sk-...` 等常見 token/key 格式。
- `password`、`passwd`、`secret`、`token`、`api_key` 後直接指定八字元以上字串的型態。
- email、Windows 使用者路徑、網域、公開／私有 IPv4 等 metadata。

掃描輸出只保留 commit、路徑、行號與分類，匹配值一律遮蔽。環境未安裝 gitleaks、trufflehog 或 detect-secrets，因此不能宣稱做過完整的高 entropy／憑證有效性掃描；quoted path 與非 ASCII 路徑也另以目前工作樹搜尋及 `git show` 人工核對。

## 仍需處理的風險

### 1. Admin workflow 會把新 secret 寫入 Actions raw log

`.github/workflows/admin.yml` 的建立 client 動作會把只顯示一次的 secret 印到 workflow log。這符合目前的領取流程，但 Actions log 是持久副本，任何能讀取該 run log 的人都可能取得憑證。

建議改成由管理後台一次性顯示，或把新 secret 寫入受權限控管的 secret store；在替代流程完成前，應限制 workflow dispatch 與 log 讀取權限，使用後也不要下載或轉貼 raw log。

### 2. Admin workflow 直接把 dispatch input 插入 shell 與 SQL

`client_name`、`line_user_id`、`client_id` 等 workflow input 目前直接出現在 shell／SQL 片段。能 dispatch workflow 的角色可能利用引號或換行繞過原本動作，在 production self-hosted runner 上執行額外指令。若一般 write collaborator 可 dispatch，風險為 Critical；若只限正式維運管理者，仍屬 High，因為它繞過 branch review。

建議把 input 先映射到 step `env`，做 allowlist／長度驗證，shell 中只使用加雙引號的變數，SQL 改用 `psql` variables 或安全參數化方式。這是 workflow 安全缺口，不是本次文件同步所能消除的問題。

### 3. 執行期資料仍可能包含個資或第三方錯誤內容

通知 payload、LINE user ID、監控 URL／header、登入 username、第三方 API 錯誤摘要及 delivery error 會依功能需求存在資料庫或 log。程式已對 secret、cookie、token、IV 等欄位設計遮蔽與加密，但部署者仍需落實 log 存取權限、資料保留與刪除程序；repo 目前沒有完整備份與保留自動化。

### 4. 範例門禁依賴未進版控的密鑰

nginx 範例以 `X-Admin-Gate` 搭配伺服器上的 `admin-gate.map`。真正密鑰不可填進範例檔或 GitHub Variables；應留在權限受控的主機檔案或 secret manager，並確保 origin 只接受可信反向代理流量。

## 已確認不是漏洞的項目

- Admin controller 沒有在每個方法顯式設定 `Cache-Control`，但 Spring Security 預設 cache header writer 會加入 `no-store`；nginx 的 `/admin/` 範例也加上 `no-store always`。
- Cognito user pool ID 與 app client ID 不是 secret。本次替換是降低 operational metadata 暴露與誤用，不代表原值已被證實有效。
- `.env`、key、PEM 與常見本機 agent/cache 目錄已被 Git／Docker context 排除；本次另補 `.codegraph`、`.agents`、`.claude`、`.worktrees` 的 Docker 排除。
