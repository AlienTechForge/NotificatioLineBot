# 隱私與敏感資訊檢查

> 檢查與處置日期：2026-09-21。此文件不記錄任何 secret 真值、私人 IP、LINE ID 或正式網域。

## 已完成的處置

- 正式 nginx 設定改為純示例 `deploy/nginx/notifyline.conf.example`，只保留示例網域與 loopback upstream。
- 以 `git-filter-repo --sensitive-data-removal` 重寫所有遠端 branch，從每個 commit 移除舊正式
  nginx 設定檔。重寫後遠端 branch 對舊路徑與該公開 IPv4 的命中均為 0。
- 額外掃描所有 commit message，發現一則說明文字仍含該 IPv4；第二次歷史重寫已將它改為
  `[redacted-public-ip]`。重寫後一般遠端 branch 的 commit message 命中為 0。
- 所有舊 commit tree 中的正式服務網域及其 base domain 已替換為 `example.com` 示例；一般遠端
  branch 的檔案內容、commit message 與作者信箱命中均為 0。
- 文件、workflow summary 與測試範例中的正式網域、部署 metadata、類 Cognito ID 已改成明確示例。
- 公開 repo 已移除並停用 GitHub Actions；production workflows、私人 GHCR 與 self-hosted runner
  存取移至私人 Operations repo。
- 私人維運 workflow 不提供 client 建立／作廢或任意 SQL input，避免 secret、LINE ID 與 shell／SQL
  injection 進入 Actions log 或正式主機。
- 正式 `.env` 留在部署主機，私人 deploy workflow 只檢查必要欄位是否存在，不輸出內容。
- 公開 repo 原有的 66 筆 Actions runs（連同關聯 log／artifact）已刪除，Actions Secrets 與
  Variables 也已清空。

## 歷史重寫後仍需注意

GitHub 的 `refs/pull/*` 是唯讀隱藏 ref，force push 無法更新。本次遠端 push 的所有一般 branch 都成功，
但 9 個既有 Pull Request refs 被 GitHub 拒絕更新。GitHub cached views、舊 PR diff 與不可達物件需由
GitHub Support 執行 purge；在完成前，不能宣稱 GitHub 端已物理清除所有副本。

其他 clone 與既有 worktree 仍可能持有 rewrite 前的 commit。這些工作副本不得直接 push；應重新 clone，
或先備份未提交變更，再 rebase／cherry-pick 到新歷史。備份、Actions artifacts 與下載過的 log 也要分別處理。

Git author email 仍屬公開 commit metadata。若作者不希望公開真實信箱，後續 commit 應使用 GitHub noreply
address；是否再改寫既有作者欄位需另行評估對簽章與 clone 的影響。

## 檢查方法與結果

以 `git rev-list`、`git grep` 與目前工作樹的定向搜尋檢查可達 commit tree，涵蓋：

- PEM private-key header。
- 常見 GitHub、AWS、Google、OpenAI token/key 格式。
- `password`、`secret`、`token`、`api_key` 後直接指定長字串的型態。
- email、Windows 使用者路徑、網域、公開／私有 IPv4 等 metadata。

掃描結果未找到可辨識的真實密碼、PAT、雲端 access key 或 private key。掃描輸出只保留分類、commit、
路徑與行號，匹配值一律遮蔽。環境未安裝 gitleaks、trufflehog 或 detect-secrets，因此這是定向檢查，
不能視為高 entropy secret scanner 的完整替代。

## 仍存在的執行期風險

### 個資與第三方錯誤內容

通知 payload、LINE user ID、監控 URL／header、登入 username、第三方 API 錯誤摘要及 delivery error
會依功能需求存在資料庫或受限 log。程式已對 secret、cookie、token、IV 等欄位設計遮蔽與加密，
部署者仍需設定 log 存取權、保留期限、備份加密與刪除程序。

### Actions 外部副本

公開 repo 的既有 runs 已刪除，但先前下載的 artifact、raw log、通知郵件、瀏覽器快取或第三方備份
不受 GitHub API 刪除影響。任何曾被印到 raw log 且仍有效的 client secret 都應視為已洩漏並輪替。

### Nginx 門禁密鑰

nginx 範例以 `X-Admin-Gate` 搭配主機上的 `admin-gate.map`。真值不得填進範例、GitHub Variables 或
workflow input，並應限制 origin 只接受可信反向代理流量。

## 已確認不是漏洞的項目

- Admin controller 未逐方法設定 `Cache-Control`，但 Spring Security 預設 header writer 會加入
  `no-store`；nginx `/admin/` 範例也設定 `no-store always`。
- 文件中的 `cli_xxx`、`example.com`、`notify.example.com`、測試 UUID 與固定時鐘值都是不可用示例。
- HMAC 測試向量刻意公開，僅用於驗證 canonical string 與簽章實作，不是 production credential。
