### 本機環境注意（非專案問題）

開發機若裝有會 MITM TLS 的防毒（本機是 Avast，`SSLKEYLOGFILE=\\.\aswMonFltProxy\…`），Maven 會失敗於：

```
PKIX path building failed: unable to find valid certification path
```

curl 正常是因為它走 Windows 憑證庫，而 Java 用自己的 `cacerts`。解法是讓 JVM 改用 Windows 憑證庫：

```bash
MAVEN_OPTS="-Djavax.net.ssl.trustStoreType=WINDOWS-ROOT" mvn -f server/pom.xml verify
```

**不要**寫進 `.mvn/jvm.config` —— 那會讓 Linux 的 CI 掛掉。建議設成使用者層級的環境變數。

### T4 實作發現

| # | 發現 | 嚴重度 |
|---|---|---|
| **F15** | 🔴 **重放防護原本靜默失效**。`RequestNonce` 主鍵是外部指定的 String，Spring Data 判定「不是新實體」而走 `merge()` —— 對已存在的列是 **UPDATE，不會違反主鍵約束**。於是重放的 nonce 被靜默覆寫，`tryConsume` 永遠回 true。**完全沒有錯誤訊息**。改用原生 `INSERT ... ON CONFLICT (nonce) DO NOTHING`，回傳影響列數判定。同樣的坑套用於 `webhook_event` | **測試抓到的真 bug** |

| **F17** | 🟡 `@AutoConfigureMockMvc` 搬到 `org.springframework.boot.webmvc.test.autoconfigure`，需加 `spring-boot-starter-webmvc-test`（**T1 F2 模組拆分第三次咬人**） | — |

| **F19** | 🟡 **MockMvc 的 `.header()` 是附加不是覆寫**。想用它覆寫成壞值來測負向路徑時，實際上會有兩個同名 header 而 `getHeader()` 取第一個 —— **壞值根本沒被讀到，測試假性通過** | 測試可信度 |

## 端到端驗證

T1–T10 全部完成後執行。

```bash

```

### 1. 基礎

- [ ] `curl localhost:8080/actuator/health` → `{"status":"UP"}`
- [ ] `docker compose logs app` 顯示 Flyway V1 套用成功

### 2. 建立 OWNER 憑證

- [ ] 跑 bootstrap CLI，記下 clientId / secret

### 3. 正向路徑

```bash
BODY='{"target":{"type":"OWNER"},"message":{"text":"hello"}}'
TS=$(date +%s); NONCE=$(uuidgen | tr 'A-Z' 'a-z')
HASH=$(printf '%s' "$BODY" | openssl dgst -sha256 -hex | awk '{print $NF}')
CANON=$(printf 'POST\n/api/v1/notifications\n%s\n%s\n%s' "$TS" "$NONCE" "$HASH")
SIG=$(printf '%s' "$CANON" | openssl dgst -sha256 -hmac "$SECRET" -binary | base64)
curl -i -X POST localhost:8080/api/v1/notifications \
  -H "Content-Type: application/json" -H "X-Client-Id: $CLIENT_ID" \
  -H "X-Timestamp: $TS" -H "X-Nonce: $NONCE" -H "X-Signature: $SIG" -d "$BODY"
```

- [ ] 回 `202` + `notificationId`
- [ ] 手機收到訊息
- [ ] `GET /api/v1/notifications/{id}` 顯示 `SUCCEEDED`

### 4. 負向路徑

- [ ] 改 body 任一字元重打 → `401 AUTH_INVALID_SIGNATURE`
- [ ] 同 nonce 重打 → `401 AUTH_NONCE_REPLAY`
- [ ] `X-Timestamp` 減 400 秒 → `401 AUTH_TIMESTAMP_SKEW`
- [ ] 連打 61 次 → `429 RATE_LIMITED`

### 5. Webhook

## 風險與已知陷阱

| 風險 | 何時會咬人 | 對策 |
|---|---|---|
| **Jackson 2.21.4 vs SDK 要 2.22.0** | T1 建置或 T5 收 webhook 時 | pom 覆寫 `jackson-2-bom.version`（[02 §5.1](02-架構設計.md#51-jackson-版本衝突必須處理)） |
| **SB 4.1 + SDK 10.1 是新組合** | 越晚發現越貴 | **T1 就驗** auto-config 與 webhook |
| **派送在交易提交前啟動** | 上線後負載下偶發，本機難重現 | `afterCommit` 觸發；用 latch 寫測試 |
| **MDC 沒傳到 `@Async`** | 事故當下才發現 log 串不起來 | `TaskDecorator`；測試斷言非同步 log 有 requestId |
| **Webhook 重送造成重複** | 網路抖動時 | `webhook_event` 冪等閘門（T5 第一件事） |
| **client secret 必須可解密** | 設計階段若誤用雜湊，整個認證做不出來 | [03 §3.1](03-權限與認證設計.md#31-為什麼不能雜湊) |
| **`APP_SECRET_ENC_KEY` 遺失** | 所有憑證報廢 | 與 DB 備份**分開**存放，至少兩份 |
| **enroll 連結即憑證** | 使用者截圖轉傳 | TTL 10 分鐘 + 單次 + 只存 hash + 私訊 |
| **`lineMessages` 可發釣魚連結** | 金鑰外洩時 | `notify:raw` scope + URI 白名單 |
| **`ALL` 燒光月額度** | 上線第一個月 | per-client 配額 + 發送前 quota 守門 |
| **斷路器把暫時故障變永久失敗** | LINE 端維護時 | `attempt_count` 不遞增 |
| **LINE 掛掉導致容器被重啟** | LINE 端故障時 | readiness **不含** LINE 狀態 |
| **自我監控告警遞迴** | LINE 掛掉時 | 獨立路徑 + 抑制窗口 + 失敗不再告警 |
| **runner 會在 server 上執行 repo 程式碼** | repo 若變 public | repo 保持 private + PR 不觸發 deploy + build 不在 self-hosted 跑（[09 §3](09-CICD與維運.md#3-安全前提)） |
| **單機佇列在重啟時掉單** | 每次部署 | DB outbox + redriver |
| **多實例排程重複執行** | 加第二個實例那天 | 先導入 ShedLock（[缺口 G12](02-架構設計.md#g12--多實例的排程重複執行--加第二個實例前必須解決)） |
| **dev 用正式 Channel 測試** | 第一次測發送時 | 另建測試用 Official Account |
