# ADR-0013 — 公開原始碼與私人維運分離

> 校訂日期：2026-09-21。

**狀態**：Accepted ｜ 2026-09-21  
**關係**：補充 [ADR-0006](0006-CICD-採-self-hosted-runner.md) 與 [ADR-0010](0010-CICD-改採-GHCR-加-SSH-部署.md)

## 背景

原始碼需要維持公開，但 self-hosted runner 位於正式主機，workflow 也曾能建立憑證、讀取資料庫及部署。即使 Fork PR 設為需核准，把 production runner、部署權限及 Actions 定義放在公開 repo 仍會擴大誤核准、設定錯誤與供應鏈攻擊的影響面。

## 決策

- `AlienTechForge/NotificatioLineBot` 維持公開，移除 `.github/workflows/` 並停用 Actions。
- 建立私人 `AlienTechForge/NotificatioLineBot-Operations`，保存 CI、GHCR image 建置、正式部署及有限維運 workflow。
- 私人 repo 每 10 分鐘讀取公開 `main` SHA。只有 SHA 改變時才跑完整測試、建立私人 image 並部署。
- 本專案的 self-hosted jobs 只存在私人 Operations repo；公開 source repo 停用 Actions，不執行公開 PR 或任意 ref。
- 正式 `.env` 留在部署主機。workflow 只驗證必要欄位，不重建、不輸出內容。
- 維運 workflow 只保留 `status`、`logs`、`restart`；client 與 owner 管理改走 Admin UI。
- 公開 repo 的 Fork PR approval policy 設為 `all_external_contributors`，即使日後重新啟用 workflow，也要先由維護者核准。

## 理由

- 公開 PR 不會取得 Actions 執行面，也不會接觸 self-hosted runner。
- 部署 workflow、package 與執行紀錄只有私人 repo 的成員可讀。
- client secret 不再被 Actions raw log 永久保存。
- 部署仍保留測試門檻、immutable SHA image、健康檢查與回滾。

## 已考慮的替代方案

| 方案 | 未採用原因 |
|---|---|
| 只設定外部 PR 全部需核准 | 可降低自動觸發，但公開 repo 仍保存 production workflow，誤核准或權限設定變更後仍可能碰到 runner |
| 公開 repo 以 `repository_dispatch` 觸發私人 repo | 需要在公開 workflow 保存可呼叫私人 repo 的 token，重新引入跨 repo 憑證 |
| 私人 repo 接 webhook | 需要另外維運公開 webhook endpoint 與驗簽服務 |
| 全部改成手動部署 | 無法維持 main 自動發布需求 |

## 後果

- 公開 main 到正式環境通常有 0–10 分鐘延遲，GitHub 排程壅塞時可能更久；可手動 dispatch 強制同步。
- CI 不再替每個公開 PR 自動回報狀態，維護者應在合併前本機執行 `mvn verify`。
- Operations repo 的 `GITHUB_TOKEN` 管理獨立私人 GHCR package；部署主機需能拉取該 package。
- 既有公開 Actions runs、PR refs 與其他 clone 不會因移除 workflow 自動消失，需另行清理。
