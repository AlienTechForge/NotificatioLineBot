## 2. 測試分層

| 層 | 工具與範圍 | 執行方式 |
|---|---|---|
| Unit | JUnit 5、AssertJ；純記憶體的 domain、認證、解析、模板、監控、Cognito SRP | `mvn -f server/pom.xml test` |
| Integration | `@SpringBootTest` + Testcontainers `postgres:18-alpine`；Flyway、Repository、MockMvc、派送、管理介面與登入 | `mvn -f server/pom.xml verify` |
| LINE API 打樁 | OkHttp `MockWebServer`；不打真實 LINE | 包含在上述兩層 |

所有 `*IT` 都繼承 `PostgresIntegrationTest`。正式與測試都由 Flyway 建 schema，測試 profile 使用假 LINE token／secret；自動化測試不可向真實 LINE API 發訊息。

## 3. 必守契約

### 3.1 HMAC 認證

- canonical string 欄位順序、LF、無結尾換行、body 原始 bytes SHA-256。
- timestamp ±300 秒、nonce 不重用、標準 Base64 HMAC-SHA256。
- 64 KiB body 上限、缺 header、未知／停用 client、錯誤簽章、重播 nonce。
- [AI 接入指南](../AI-接入指南.md) §3.4 的固定測試向量必須保持通過。

### 3.2 權限、配額與冪等

- `SELF`、`OWNER`、`USER`、`ALL` 與五種 scope 的允許／拒絕矩陣。
- 省略 target 時使用 client 預設；明確 target 仍照 scope 檢查。
- 每日配額以去重後收件人數計；超限整筆拒絕。
- 相同 client + `Idempotency-Key` + 相同 body 重播既有結果；不同 body 回 409。

### 3.3 派送與可靠性

- 500 人分批、去重、優先級與 `FOR UPDATE SKIP LOCKED` claim。
- 成功、部分成功、終局失敗與最多五次可重試失敗。
- retry key 沿用、1/2/4/8 秒退避與 jitter。
- circuit breaker／rate limiter 的 `DEFERRED` 不增加 attempt count。
- `scheduledAt` 未到期不可取件；取消只作用於未開始的 QUEUED 通知。
- 202 僅表示已持久化；`SUCCEEDED` 表示 LINE 接受批次，不代表手機已讀或實際顯示。

### 3.4 LINE webhook 與好友名單

- SDK 簽章驗證、webhook event id 去重。
- follow／unfollow、指令全形空白正規化與未知指令。
- Profile 同步 404 → BLOCKED；其他錯誤不可誤停用。
- webhook redelivery 可能重複，不能只依 HTTP 重試假設一次送達。

### 3.5 API 監控

- SSRF：只允許 HTTPS、公網 DNS、禁止 redirect、限制 1 MiB response。
- WHOLE_BODY、EXTRACTED、NEW_ITEMS 三種比對模式。
- EXTRACTED 缺欄位或 JSON null 視為解析失敗並保留舊 baseline；空字串是合法值。
- 初次完整結果只建立 baseline，不發變更通知。
- header、cookie、monitor secret、登入密碼與 token 不出現在一般 DTO 或 log。
- cURL／fetch／JSON 匯入只解析文字，不 eval；64 KiB 上限。

### 3.6 站台登入

- Cognito endpoint 僅由 region、user pool ID 組成，不接受任意 URL。
- SRP 計算、pool name、固定 UTC timestamp 格式與 refresh fallback。
- password、refresh token、短效 token 使用各自 AAD 加密。
- 同一登入在單 JVM 內合併併發登入；401 使 token 失效並只重試一次。
- 永久登入失敗停用設定；測試登入可能更新 token 快取或停用設定。
- API 與頁面不得回傳密碼、refresh token、token 密文或 IV。

### 3.7 管理介面

- 未登入的 `/admin/api/**` 回 401；頁面導向登入。
- session cookie、CSRF、登出、停用管理介面時的 fail-closed 行為。
- 30 個 controller 方法映射的成功、驗證與權限邊界。
- 通知列表／明細可看保存中的內容；monitor header 明文只在專用已認證端點回傳。
- 敏感與測試回應不應被快取；Spring Security 預設 header writer 與 nginx 再加一層 `no-store`。

## 4. 覆蓋率門檻

`server/pom.xml` 的 JaCoCo check 是合併 surefire 與 failsafe 執行資料後驗證：

| 範圍 | line coverage 最低值 |
|---|---:|
| 全 bundle | 80% |
| `auth` | 95% |
| `notification.dispatch` | 90% |
| `webhook` | 90% |
| `client` | 90% |

`config`、啟動類別與產生式 DTO 等排除項以 `pom.xml` 為準。覆蓋率門檻只能證明程式行被走過，不能取代狀態機、併發與安全邊界的語意斷言。

## 5. CI

`.github/workflows/ci-cd.yml` 的 `test` job 在 GitHub-hosted runner 執行 Java 21 與 `mvn verify`。`image` 依賴 `test`，所以測試或 JaCoCo 失敗不會 build／push image；PR 不執行 deploy，main 才交由 self-hosted runner 部署。

需要重新核對數字時，使用：

```bash
find server/src/test/java -name '*Test.java' | wc -l
find server/src/test/java -name '*IT.java' | wc -l
grep -rhoE '@Test\b|@ParameterizedTest' --include='*.java' server/src/test/java | wc -l
mvn -f server/pom.xml verify
```

實際執行數讀 `server/target/surefire-reports/TEST-*.xml` 與 `failsafe-reports/TEST-*.xml` 的 `tests` 屬性。

## 6. 已知缺口

- `enrollment_token` 與 `audit_log` 只有 schema，沒有正式 Java 功能，因此沒有可驗收的完整流程。
- 管理前端是原生 JS，目前沒有瀏覽器端行為測試；後端整合測試不能取代拖曳、對話框、hash route 等 UI 驗證。
- SSRF guard 在 DNS 檢查後由 HTTP client 再解析一次，仍有 DNS rebinding 時間差；測試可證明規則，不能消除架構風險。
- 多實例下的排程、rate limiter、circuit breaker 與登入鎖不是共享狀態；上線第二個實例前需另補協調測試與實作。
- POC 的 migration／資料表斷言仍停在 V1，會對目前 V1～V7 產生已知失敗；詳見 [poc/README](../../poc/README.md)。
