# 14 — 模板輸入輔助

> 校訂日期：2026-09-21。依 2026-09-21 main 的程式碼核對；歷史方案與未實作項目另行標示。

> 讓使用者不用背變數、不用手打佔位符。
>
> 延伸自 [13-監控計算欄位設計](13-監控計算欄位設計.md)。純前端 + 一點點預設值邏輯，
> 不動任何後端契約。

---

## 1. 起因

實際使用時踩到的兩個坑：

1. 使用者寫了 `{{item.Airplane}}`，渲染出 `—`。原因：`item.*` 只在 `NEW_ITEMS`
   模式逐筆渲染時才有值，該監控是 `EXTRACTED` 模式。**UI 完全沒有提示這件事。**
2. 使用者在「試算」看到 `{{old.Airplane}}` 是 `—`，以為壞了。原因：試算只抓一次，
   沒有「上一次」可比（`ApiMonitorTestRunner` 明確傳 `Map.of()` 當 `previousValues`）。
   正式輪詢會有值。**試算面板沒有標註這個差異。**

兩者都不是 bug，都是「使用者無從得知」。

---

## 2. 預設訊息模板

### 2.1 內容

```
{{monitor.name}}
原本：{{old.<欄位>}}
現在：{{value.<欄位>}}
時間：{{now}}
```

### 2.2 `<欄位>` 必須是動態的

**不可寫死任何欄位名。** 欄位名來自使用者自己的解析規則，寫死等於對其他監控都是錯的。

規則：

- 開啟「建立監控」時，若已有解析規則 → 用**第一條**規則的 `name`
- 尚無規則 → 用 `NAME` 佔位
- 使用者新增第一條解析規則時，**若模板仍是未經修改的預設值**，自動用新規則名重寫一次
- 使用者一旦手動改過模板，就再也不自動覆寫（用一個 pristine 旗標追蹤，
  不要用「內容等於預設字串」來判斷 —— 使用者可能改回一模一樣的內容）

編輯既有監控時**不套用**任何預設，一律顯示已存的值。

---

## 3. 說明文字改表格

現有說明表格位於 `static/admin/index.html`；欄位及動態候選由 `assets/app.js` 管理。

### 3.1 訊息模板

| 變數 | 意義 | 何時有值 |
|---|---|---|
| `{{value.欄位}}` | 本次抓到的值 | WHOLE_BODY／EXTRACTED，需有對應規則；NEW_ITEMS 使用 item.* |
| `{{old.欄位}}` | 上一次的值 | **僅正式通知**。試算一律 `—`（試算只抓一次，沒有上一次） |
| `{{item.欄位}}` | 該筆新項目的欄位 | **僅 `NEW_ITEMS` 模式**，逐筆渲染時 |
| `{{monitor.name}}` | 監控名稱 | 一律 |
| `{{now}}` | 現在時間 `MM/dd HH:mm`（台北） | 一律 |

行為：打錯 → `—`（不原樣輸出）；值為 null → `—`；渲染後截到 4500 字；
`NEW_ITEMS` 每筆各渲染一次，最多 20 筆。

### 3.2 請求模板（URL／header／body）

| 變數 | 產出 |
|---|---|
| `{{now.epochSeconds}}` | Unix 秒 |
| `{{now.epochMillis}}` | Unix 毫秒 |
| `{{now.iso8601}}` | `2026-08-24T03:00:00Z`（UTC，秒精度） |
| `{{now.format:PATTERN}}` | 自訂格式，台北時區 |
| `{{now±N[smhd].…}}` | 位移，例 `{{now-7d.format:yyyy-MM-dd}}` |
| `{{uuid}}` | 隨機 UUID（同一次請求內同值） |
| `{{computed.名稱}}` | 計算欄位 |

**與訊息模板刻意相反**：請求模板打錯佔位符會在**存檔時直接擋（400）**。
訊息模板打錯只毀一則訊息；請求模板打錯是每一輪都打到錯的網址。

### 3.3 計算欄位的「輸入」

請求模板全部變數，外加 `{{secret.名稱}}`。
`{{secret.*}}` **只能寫在這裡**，不能出現在 URL／header／body。

## 4. `{{` 自動完成

### 4.1 掛在哪些欄位

| 欄位 | 變數集合 |
|---|---|
| `monTemplate` | §3.1 訊息模板 |
| `monUrl` / `monHeaders` / `monBody` | §3.2 請求模板 |
| 計算欄位的 `input` | §3.3（請求模板 + `secret.*`） |

**給錯清單比沒有更糟** —— 使用者會信任選單，選到一個在該情境無效的變數，
然後得到 `—` 或存檔被擋，比自己查文件更困惑。這三組必須分開。

### 4.2 清單內容依當下表單狀態動態產生

- `value.X` / `old.X`：對**每一條已定義的解析規則**各產生一項
- `item.X`：同上，但**僅當比對模式 = `NEW_ITEMS`** 才列入
- `computed.X`：對每一個已定義的計算欄位
- `secret.X`：對每一個已定義的密鑰（含既有的與這次新填的）
- 固定項（`monitor.name`、`now`、`now.epochSeconds`…）永遠列入

每一項顯示：變數 + 一句話說明。`old.*` 那句要寫「試算時為 —」。

### 4.3 互動

- 觸發：輸入 `{{` 之後，或按 `Ctrl+Space`
- 輸入 `{{` 之後繼續打字 → 即時過濾
- `↑` `↓` 移動、`Enter` 或 `Tab` 選取、`Esc` 關閉、滑鼠點選
- 選取後插入完整的 `{{變數}}`，游標移到 `}}` 之後
- 失焦關閉
- 選單定位在游標附近，且不可被抽屜裁切（注意 `dialog` 的 `overflow`）

### 4.4 前端約束

- **全部 DOM 寫入走 `textContent` / `el()`，禁 `innerHTML`** —— 選單內容含使用者
  自訂的規則名稱與密鑰名稱
- 沿用既有 CSS token（`--c-*`、`--sp-*`、`--radius*`），不引入新色、不掛外部資源
- 尊重 `prefers-reduced-motion`
- 不可弱化 `dialog:not([open]) { display: none }`、`dialog[open] { display: flex }`、
  `[hidden] { display: none !important }`
- 鍵盤可完全操作；選單加 `role="listbox"`，選項加 `role="option"` 與
  `aria-selected`

## 5. 試算面板標註

試算結果若模板含 `{{old.*}}`，在結果旁顯示一行提示：

> 試算沒有「上一次」可比，`{{old.*}}` 一律顯示 —。正式通知時會有值。

同理，比對模式非 `NEW_ITEMS` 卻用了 `{{item.*}}` → 提示該變數在此模式下永遠是 `—`。

這兩條提示是本文件 §1 兩個真實坑的直接解法，不可省略。

---

## 6. 驗收

- 新建監控 → 模板已預填，且欄位名取自第一條解析規則
- 尚無規則時預填 `NAME`；新增第一條規則後自動更新；手動改過後不再自動覆寫
- 三個情境的 `{{` 選單各自只列該情境有效的變數
- 選單可純鍵盤操作
- `$()` id 對照零懸空
- 零 `innerHTML`
- `mvn verify` 綠（純前端改動，但靜態資源會被打包）

## 7. main 上的互動現況

- 自動完成選單跟隨輸入欄位定位，在 dialog 內使用可見區域限制；以方向鍵切換會把選取项捲入可見範圍。
- 頁面／抽屜捲動可關閉選單，選單自己的捲動不应把選單立刻關掉。
- 站台登入欄位由 loginId 選擇，不在變數清單暴露 password／token。
- EXTRACTED 缺值／JSON null 現在回解析失敗，不會因缺值產生「現在：—」的變更通知；訊息模板對其他情境的未知變數仍輸出 —。
- 本文件的驗收列表是 UI 檢查要求；Maven verify 並不替代實際瀏覽器的鍵盤與捲動測試。
