新增監控

1從瀏覽器貼上

貼上開發者工具複製的請求，下面的網址、方法、header 會自動填好。也可以略過，全部手動填。

要帶登入狀態請用 Chrome 的「Copy as cURL (bash)」。

為什麼不能用「Copy as fetch」

cookie 是瀏覽器自行附加的 forbidden header，不會出現在 fetch 複製出來的字串裡。貼了會一直 401，不是設定壞了。貼上的內容含 cookie 時會自動存進「登入狀態」頁，不會留在這個監控自己的 header 裡。

自訂 JSON 格式可直接餵給 AI，請它照這個 schema 產生一份可匯入的設定。

2基本設定

實際下限依伺服器設定而定，太低會在儲存時被拒絕。

3要抓哪個 API

只允許 https，不可指向內網位址。

扁平的字串對字串 JSON。留空 = 不變更既有 header。

目標站台的 token 會過期時選這個，系統會自動登入取得新 token 再抓。

什麼時候需要

如果貼上的 header 裡有 Authorization 而且只能撐一小時左右，那就是短效 token，手動貼的會過期。改用這裡選一組登入設定，系統每次抓取前會確認 token 還有效，過期就自動換一個。登入設定在左側「站台登入」頁建立。

4怎麼判斷有變化

決定「什麼算變了」。抓下來的內容用「先測一次」展開成樹，點節點就能填進抽取欄位。

抽取欄位

JsonPointer 位置，訊息模板用 {{value.NAME}} 引用。

此模式下抽取欄位相對於每個項目解讀，模板用 {{item.NAME}} 引用。

5通知內容

輸入 {{ 會跳出可用變數清單（Ctrl+Space 手動叫出）。

完整變數對照表

訊息模板（monTemplate）

變數意義何時有值
{{value.欄位}}本次抓到的值一律
{{old.欄位}}上一次的值僅正式通知。試算一律 —
{{item.欄位}}該筆新項目的欄位僅 NEW_ITEMS 模式，逐筆渲染時
{{monitor.name}}監控名稱一律
{{now}}現在時間 MM/dd HH:mm（台北）一律

打錯 → —（不原樣輸出）；值為 null → —；渲染後截到 4500 字；NEW_ITEMS 每筆各渲染一次，最多 20 筆。

請求模板（monUrl／monHeaders／monBody）

變數產出
{{now.epochSeconds}}Unix 秒
{{now.epochMillis}}Unix 毫秒
{{now.iso8601}}2026-08-24T03:00:00Z（UTC，秒精度）
{{now.format:PATTERN}}自訂格式，台北時區
{{now±N[smhd].…}}位移，例如 {{now-7d.format:yyyy-MM-dd}}
{{uuid}}隨機 UUID（同一次請求內同值）
{{computed.名稱}}計算欄位

與訊息模板刻意相反：請求模板打錯佔位符會在存檔時直接擋（400）。

計算欄位的「輸入」

請求模板全部變數，外加 {{secret.名稱}}。{{secret.*}} 只能寫在這裡，不能出現在 URL／header／body。

6簽章與計算欄位 — 目標 API 需要動態簽章時才需要

密鑰（signing secret）

計算欄位用 {{secret.NAME}} 引用。值加密儲存，後台只顯示名稱與「已設定」。

計算欄位

依序求值，可串接多段雜湊；模板用 {{computed.NAME}} 引用結果。

串接規則

每個欄位的 steps 依序套用，前一段的輸出字串就是後一段的輸入——這是雙重雜湊（例如 MD5(MD5(x).toUpperCase()).toUpperCase()）能表示的原因。輸入可用 {{secret.NAME}}、{{now.epochSeconds}}、{{uuid}}，以及更早定義的 {{computed.NAME}}。

7防洗版與開關 — 冷卻、每日上限、失敗通知

發過一次通知後，這段時間內不再發。

開關

8先測一次

用目前填寫的設定實際打一次目標 API。不會發送、不會存檔。

「再抓一次比對」會標出跟上次不一樣的欄位——每次都在變的欄位（時間戳、隨機碼）不適合當監控目標。

新增站台登入

1這組登入叫什麼

建立監控時會用這個名稱在下拉選單裡選。

2Cognito 設定

目標站台的 user pool 資訊。通常在網站前端的設定檔（例如 envconfig.js）裡找得到。

Region 前綴必須與 user pool ID 一致，否則存檔會被擋。

3帳號密碼

密碼加密後儲存，之後任何畫面與 API 都讀不回來。登入走 SRP，密碼不會離開這台伺服器。

建立時必填。

密碼錯誤會怎樣

連續登入失敗會被對方鎖帳號，所以帳密錯誤時這組登入會立刻自動停用並發 LINE 通知，不會反覆重試。修正密碼後在這裡重新啟用即可。

4Token 注入方式 — 預設適用多數站台

必須含 {token}。多數站台用 Bearer {token}，少數送裸 token。

開關
